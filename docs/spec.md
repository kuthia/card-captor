# Card Captor 기능 명세

## 목적

Notion GTD에서 이미 관리하는 특정 뷰의 페이지를 데스크톱 캐릭터가 들고 있도록 한다. 사용자는 Notion 창을 계속 열어두지 않고 카드 목록을 훑고 필요한 페이지로 이동한다.

## 확정한 요구사항

| 구분 | 동작 |
| --- | --- |
| 실행 환경 | macOS·Windows 데스크톱 앱 |
| 캐릭터 | 주 모니터의 작업 영역 안에서 자율 이동하며 드래그로 배치 가능 |
| 렌더링 | WebGL 캐릭터 렌더러와 정적 SVG 대체 경로. 카드 UI와 렌더러 수명 주기 분리 |
| 캐릭터 선택 | 카드 패널에서 기본 로봇·Rive 샘플 선택. 일반 모드는 저장·재실행 복원, 기존 설정은 기본 로봇으로 시작 |
| 상시 실행 | 걷기·캐릭터 애니메이션 최대 30 FPS. 기본 로봇은 유휴 시 연속 프레임 중지, Rive 모델은 대기·열람 중 모션 유지. 커서 거리별 감시 주기 조절 |
| 카드 탐색 | 캐릭터에서 카드 목록을 펼침. 목록·설정 탐색 중 이동 정지 |
| 데이터 선택 | 사용자가 지정한 기존 Notion 뷰의 필터·정렬을 따름 |
| 카드 표시 | 제목·상태·상태 색상·날짜·원본 링크를 공통 표시 모델로 변환 |
| 상태 변경 | 카드의 상태 버튼에서 실제 Notion 선택지를 조회하고 선택 즉시 해당 속성만 저장 |
| 조회 범위 | 최대 20개 표시. 추가 결과 여부 안내 |
| 갱신 | 기본 60초, 최소 30초, 수동 새로고침 제공. 오프라인에서는 중지 |
| 실패 처리 | 기존 목록 유지, 마지막 성공 시각과 실패 상태 표시 |
| 확장 | Paca를 별도 Provider로 추가할 수 있도록 UI와 조회 구현 분리 |

## 사용자 흐름

1. 첫 실행에서 캐릭터와 연결 안내를 표시한다.
2. 사용자가 카드 패널의 설정에서 Notion 뷰 링크·ID와 토큰을 저장한다.
3. 저장된 뷰를 조회하고 카드 목록을 표시한다.
4. 카드 제목을 누르면 원본 페이지를 열고, 상태 버튼을 누르면 현재 데이터 소스의 상태 선택지를 펼친다.
5. 선택한 상태의 저장 성공을 확인한 뒤 카드에 반영하고 뷰를 다시 조회한다. 필터에서 제외된 카드는 재조회 결과에 따라 목록에서 사라진다.
6. 카드 패널을 닫으면 사용자가 설정한 이동 상태로 돌아간다.

브라우저 개발 모드는 명시적인 미리보기로 동작한다. 실제 Notion 토큰을 입력하거나 외부 서비스를 호출하지 않으며 임의의 사용자 업무를 만들어 표시하지 않는다.

## 상호작용 정책

- `idle`, `walking`, `dragging`, `browsing`, `suspended` 상태를 구분한다.
- 카드·설정 패널 열림과 드래그 상태는 자율 이동보다 우선한다.
- 드래그 좌표와 패널 위치는 작업 영역 안으로 제한한다.
- 투명한 빈 영역은 아래 앱의 포인터 입력을 가로채지 않는다.
- 숨김·네트워크 단절 등 중지 조건이 해제되어도 갱신 요청은 중복 실행하지 않는다.
- 캐릭터 변경은 카드 패널과 현재 목록을 유지한다. 일반 모드는 저장 성공 뒤 적용하고, 저장 실패 시 기존 선택과 오류 안내를 유지한다.

## 데이터와 권한 정책

- Notion 쓰기는 현재 카드 목록에 포함된 페이지의 명시적으로 선택한 상태 속성에만 허용한다. 뷰·필터·상태 선택지·본문은 변경하지 않는다.
- 상태 선택지는 페이지의 현재 데이터 소스 스키마에서 읽는다. 여러 상태 속성이 있으면 사용자가 속성을 선택하며, 상태 속성이 없을 때만 이름이 `Status`·`상태`·`진행 상태`인 Select 속성을 지원한다.
- 한 번 조회한 카드의 상태 옵션은 앱 실행 중 메모리에 보관한다. 다시 열면 이전 목록을 즉시 표시하고 뒤에서 매번 재조회하며, 첫 조회에만 로딩 표시를 사용한다. 재조회 실패 시 이전 옵션과 오류 안내를 유지한다.
- 상태 옵션 캐시는 카드 패널을 닫아도 유지하되, 연결 토큰·뷰 변경 및 연결 해제 시 비운다. 현재 목록에서 빠진 카드의 캐시도 정리한다. 저장에 성공한 현재 선택값은 캐시에 즉시 반영하며 오래된 조회가 이를 덮지 못하게 한다. 실제 쓰기의 최신 속성·선택지 재검증은 유지한다.
- 상태 배지·선택지의 배경·글자·점은 Notion의 색상 토큰을 따른다. 2026-11-17 실제 Notion 밝은 테마의 CSS 색상을 기준으로 하며, 색상 누락·알 수 없는 토큰은 중립 회색으로 표시한다. 현재 앱은 밝은 테마만 제공한다.
- 상태 변경 직전에 속성·선택지 ID를 재검증하고 한 속성만 PATCH한다. 쓰기 권한 부족·삭제된 선택지·네트워크 실패를 한국어로 안내한다.
- 저장 성공 전에는 기존 상태를 유지한다. 저장 성공 뒤 뷰 재조회에 실패하면 성공한 변경은 유지하고 재조회 실패를 별도로 표시한다. 통신 중 결과가 불명확하면 새로고침으로 확인하도록 안내한다.
- 상태 변경·새로고침·연결 변경은 네이티브에서 직렬화하여 오래된 조회가 변경 결과를 덮지 않게 한다. 뷰 쿼리 생성·삭제는 조회용 임시 결과의 수명 관리에만 사용한다.
- 토큰은 OS 자격증명 저장소에 저장하고, 저장소 사용 실패 시 평문 파일로 대체하지 않는다.
- UI에는 토큰 존재 여부만 반환한다. 저장 완료 후 입력값을 비운다.
- 앱 설정과 카드 캐시는 로컬 데이터 파일로 보관하며 토큰은 포함하지 않는다.
- 인증·권한 오류와 빈 결과를 구분한다. 실패를 빈 카드 목록으로 바꾸지 않는다.
- 원본 열기는 조회한 카드의 식별자를 기준으로 처리한다.
- 캐릭터 선택은 `AppConfig.characterBackend`의 `robot`·`rive`만 허용한다. 필드가 없는 기존 설정은 `robot`으로 읽는다. 전용 `set_character_backend` 명령은 이 필드만 저장하며 키체인·Notion을 호출하거나 연결 설정·카드 캐시를 변경하지 않는다. 일반 연결 설정을 저장할 때도 현재 캐릭터 선택을 유지한다.
- 합성 카드 검증 모드와 브라우저 미리보기의 캐릭터 변경은 메모리에만 반영한다.

## 후속 범위

| 항목 | 확장 시점에 결정할 내용 |
| --- | --- |
| Paca | 서버 주소·인증·저장된 필터 조회 계약. 현재 `http://localhost:3090` 로컬 서비스 확인 |
| 다중 모니터 | 모니터 선택·경계 이동·해상도 및 DPI 변경 정책 |
| 추가 카드 쓰기 | 본문·날짜·담당자 등 상태 이외 속성의 편집 필요성 |
| 캐릭터 리소스 | 자체 스프라이트와 애니메이션 교체 방식 |
| 고급 표현 | Live2D 또는 3D 렌더러·모델 리소스 선택과 전력 측정 |
| 배포 | 서명·공증·설치 파일·자동 업데이트 |

Paca의 쿼리 의미가 확인되기 전에는 공통 필터 언어를 만들지 않는다. Notion의 `viewId`와 Paca의 저장된 검색 식별자는 각 Provider가 해석한다.

| AC11 | 상태 버튼에서 실제 스키마 선택지로 변경하고 원본 페이지는 열리지 않음 | API 모의 서버 + UI 확인 |
| AC12 | 잘못된 카드·속성·선택지는 쓰기 거부하며 다른 속성은 변경하지 않음 | API 요청 본문·명령 경계 테스트 |
| AC13 | 저장 중 중복 쓰기 방지, 실패 시 기존 상태 유지, 성공 후 저장된 뷰 재조회 | 비동기 UI·직렬화 테스트 |

CPU·GPU·전력은 동일 기기에서 대기, 이동, 카드 열람, 숨김 상태를 각각 측정한다. 절감률은 이전 구현과 같은 조건의 측정 결과가 있을 때만 기록한다.

- 프런트엔드 로직·렌더러·측정 상태 테스트 30개 통과

- macOS 디버그 앱 번들 생성 성공
- 브라우저 미리보기에서 카드 패널 열기·닫기, 키보드 조작, 자격증명 입력 비활성 확인
- 배포용 CSP를 적용한 브라우저에서 WebGL 렌더링 경로와 카드 열기·이동 동작 확인
- macOS M1 Max의 실제 릴리스 앱에서 유휴·이동·정적 카드 열람을 각 30초씩 3회 측정. [측정 보고서](measurements/2026-11-17-macos/REPORT.md)와 원본 데이터 보관

Windows CI, 네이티브 창의 실제 클릭 통과와 포커스, 실제 Notion 계정 연결은 위 수용 기준의 수동 검증 항목으로 남아 있다.

### 상태 편집과 캐릭터 사양 추가 검증

- 프런트엔드 테스트 33개, 네이티브 측정 feature 포함 테스트 25개 통과.
- TypeScript·프런트엔드 빌드, Rust Clippy 경고 검사 통과.
- Notion HTTP 모의 서버에서 최소 PATCH 본문, 존재하지 않는 속성·선택지 차단, 권한 오류·불확실한 쓰기, null Status 기본값·데이터 소스별 메타데이터 조회 재사용을 확인.
- 상태 저장 후 뷰 재조회는 별도 단계이며, 재조회 실패가 이미 성공한 쓰기를 실패로 바꾸지 않도록 구현·검토.
- macOS 릴리스 앱을 다시 빌드·실행하여 기존 연결의 카드 5개와 실제 Notion 상태 선택지·현재 상태 표시를 확인.
- 상태 색상 전파 추가 후 네이티브 테스트 26개 통과. API 색상·기본 상태 색상·변경 응답의 색상 보완·기존 캐시 호환을 확인.
- 상태 옵션 캐시 추가 후 프런트엔드 테스트 41개 통과. 백그라운드 재조회 실패 시 기존 옵션 유지, 중복 조회 병합, 연결·카드 목록 변경 후 늦은 응답 폐기, 확정된 상태 변경 보호를 검증.
- macOS 릴리스 앱에서 카드 패널을 닫았다 다시 연 뒤 상태 옵션이 로딩 화면 없이 표시되는 것과 SVG 드롭다운 화살표의 수직 정렬을 확인.
- [캐릭터 리소스 사양](character-sprites.md)의 크기·상태·타이밍과 소스 상수·문서 링크를 대조.

실제 업무 카드의 상태 쓰기와 Windows 수동 검증은 수행하지 않았다.

### Rive 샘플의 별도 검증 모드

2026-11-18 공식 MIT `Centaur` 샘플을 연결했다. 프런트엔드 테스트 57개·네이티브 테스트 29개와 프로덕션 빌드·Clippy 검사를 통과했다. macOS 릴리스 앱에서 대기·보행·실제 드래그·합성 카드 열람과 기본 로봇 왕복 전환을 확인했다. 실제 설정·키체인·Notion 명령은 검증 모드에서 차단한다. 상태 매핑·실행 조건·증거와 미검증 범위는 [Rive 동작 검증](rive-validation.md)을 따른다.

후속으로 일반 모드의 캐릭터 선택 저장을 추가했다. 프런트엔드 57개·네이티브 33개 테스트 통과 후, macOS 기본 릴리스 앱에서 실제 Notion 카드 5개와 Rive 표시, 새로고침, 재실행 후 선택 복원을 확인했다. 일반 모드의 실제 계정 조회와 합성 카드 검증 모드는 별도로 유지한다.
