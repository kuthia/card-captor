# Card Captor 기능 명세

## 목적

데스크톱 캐릭터가 Codex 작업 상태와 Notion GTD 카드를 챙긴다. 사용자는 작업 완료·확인 요청을 알림으로 확인하고, 피드에서 원본 대화나 카드로 이동한다.

## 확정한 요구사항

| 구분 | 동작 |
| --- | --- |
| 실행 환경 | macOS·Windows 데스크톱 앱 |
| 캐릭터 | 주 모니터의 작업 영역 안에서 자율 이동하며 드래그로 배치 가능 |
| 캐릭터 선택 | 카드 덱의 캐릭터 선택에서 캡터·웰루니를 미리 보고 즉시 변경. Notion 연결 없이 선택 가능하며 재실행 후 유지 |
| 렌더링 | WebGL 캐릭터 렌더러와 정적 SVG 대체 경로. 카드 UI와 렌더러 수명 주기 분리 |
| 상시 실행 | 걷기·캐릭터 애니메이션 최대 30 FPS, 유휴 시 연속 프레임 중지, 커서 거리별 감시 주기 조절 |
| 카드 탐색 | 캐릭터에서 카드 목록을 펼침. 목록·설정 탐색 중 이동 정지 |
| 데이터 선택 | 사용자가 지정한 기존 Notion 뷰의 필터·정렬을 따름 |
| 카드 표시 | 제목·상태·상태 색상·날짜·원본 링크를 공통 표시 모델로 변환 |
| 상태 변경 | 카드의 상태 버튼에서 실제 Notion 선택지를 조회하고 선택 즉시 해당 속성만 저장 |
| 조회 범위 | 최대 20개 표시. 추가 결과 여부 안내 |
| 갱신 | 기본 60초, 최소 30초, 수동 새로고침 제공. 오프라인에서는 중지 |
| 실패 처리 | 기존 목록 유지, 마지막 성공 시각과 실패 상태 표시 |
| 확장 | Paca를 별도 Provider로 추가할 수 있도록 UI와 조회 구현 분리 |
| Codex 작업 피드 | 로컬 Codex 앱의 읽기 전용 IPC를 구독해 작업 상태·최근 결과·활동을 표시. Notion 연결과 독립 |
| Codex 반응 | 새 승인·입력 대기, 턴 완료·실패에 인앱 알림·OS 알림·사운드 제공. 알림과 사운드는 개별 설정 |
| Codex Mini 말풍선 | 캐릭터 곁에 대화 제목 1줄·최신 진행 내용 1줄 표시. 진행 중·입력 대기 동안 실시간 갱신하고 완료·실패·중단은 6.5초 뒤 숨김. 최초 과거 완료는 표시하지 않음 |
| Codex 피드 탐색 | 팝업 피드의 작업·최근 활동 항목 전체를 클릭하거나 키보드로 실행하면 해당 `codex://threads/{id}`를 OS에서 열기 |

### Codex 관측 정책

- 초기 범위는 macOS/Linux의 같은 사용자 소유 Unix 소켓이다. `$CODEX_HOME/ipc/ipc.sock`, `~/.codex/ipc/ipc.sock`, 기존 임시 소켓 순으로 확인한다. 소켓을 생성·삭제하거나 Codex 자격증명·설정을 읽지 않는다. Windows에서는 지원 범위를 명시한다.
- 초기화, 소유자 확인, 상태 구독·해제, 처리 불가 응답만 송신한다. 작업 시작·입력 전달·중지·승인은 구현하지 않는다. 사용자가 피드의 원본 열기를 누르면 관측한 대화를 Codex 앱에서 연다.
- 창의 작업 선택 이벤트와 최근 14일의 세션 파일명(후보 최대 32개)에서 로컬 작업을 발견한다. 파일 내용은 읽지 않으며 실제 앱 소유자가 응답한 세션만 최대 12개 구독한다. 창에서 다른 작업으로 이동해도 기존 구독을 유지한다. 앱의 전체 과거 대화를 열거하지 않는다. 피드에 관측 범위를 안내한다.
- 최초 스냅샷·재접속·리비전 불일치 후 재동기화는 기준 상태로 취급한다. 과거 완료는 알리지 않으며 `idle`만으로 완료를 추정하지 않는다. 관측 중인 턴의 상태 전환을 기준으로 판단한다.
- 동일 세션·턴·이벤트·입력 요청을 중복 알리지 않는다. 재연결 시 캐시와 미확인 상태를 구분하고 다시 기준 상태를 받은 뒤 반응을 재개한다.
- 말풍선은 OS 알림·사운드와 독립된 작업 상태 표시다. 최신 assistant 진행 내용을 사용하고 내용이 없으면 상태 문구로 대체한다. 피드 팝업을 열면 말풍선을 숨기며 피드와 말풍선은 같은 정규화된 상태를 따른다. 연결이 끊기거나 관측을 끄면 말풍선을 숨긴다.
- 원문은 패치 적용을 위해 제한된 메모리에만 보관한다. 프레임·세션 개수·피드 크기를 제한하며 UI에는 제목·상태·짧은 결과만 전달한다. 전체 대화·도구 인자·자격증명은 저장·로그·알림에 포함하지 않는다.
- 브라우저에서는 명시적 합성 시나리오로 피드·알림을 검증하고 실제 IPC·OS 알림을 사용하지 않는다. 측정 모드에서는 Codex 연결·사운드·알림을 모두 중지한다.

## 사용자 흐름

1. 첫 실행에서 캐릭터와 Codex 작업 피드를 표시한다. Codex 앱에서 열린 로컬 작업을 읽기 전용으로 따라간다.
2. 사용자가 카드 패널의 설정에서 Notion 뷰 링크·ID와 토큰을 저장한다.
3. 저장된 뷰를 조회하고 카드 목록을 표시한다.
4. 카드 제목을 누르면 원본 페이지를 열고, 상태 버튼을 누르면 현재 데이터 소스의 상태 선택지를 펼친다.
5. 선택한 상태의 저장 성공을 확인한 뒤 카드에 반영하고 뷰를 다시 조회한다. 필터에서 제외된 카드는 재조회 결과에 따라 목록에서 사라진다.
6. 카드 패널을 닫으면 사용자가 설정한 이동 상태로 돌아간다.

브라우저 개발 모드는 명시적인 미리보기로 동작한다. 실제 Notion 토큰을 입력하거나 외부 서비스를 호출하지 않으며 임의의 사용자 업무를 만들어 표시하지 않는다.

## 상호작용 정책

- `idle`, `walking`, `dragging`, `browsing`, `suspended` 상태를 구분한다.
- 카드·설정 패널 열림과 드래그 상태는 자율 이동보다 우선한다.
- 캐릭터 선택 패널에서도 자율 이동을 멈춘다. 선택은 라디오 입력으로 키보드 조작할 수 있고, 저장 실패 시 이전 캐릭터와 오류 안내를 유지한다.
- 캐릭터 변경 시 이전 렌더러·예약·텍스처를 해제한다. 웰루니는 제공된 캐릭터보드의 정면 모습을 바탕으로 한 로컬 투명 PNG를 사용하며, WebGL 실패 시에도 같은 캐릭터를 표시한다.
- 데스크톱에서는 캐릭터 선택을 앱 설정에 저장하고, 브라우저 미리보기에서는 로컬 저장소에 저장한다. 기존 설정에 선택값이 없으면 캡터를 사용하고, Notion 연결 해제 시 선택을 유지한다.
- 드래그 좌표와 패널 위치는 작업 영역 안으로 제한한다.
- 투명한 빈 영역은 아래 앱의 포인터 입력을 가로채지 않는다.
- 숨김·네트워크 단절 등 중지 조건이 해제되어도 갱신 요청은 중복 실행하지 않는다.

## 데이터와 권한 정책

- Notion 쓰기는 현재 카드 목록에 포함된 페이지의 명시적으로 선택한 상태 속성에만 허용한다. 뷰·필터·상태 선택지·본문은 변경하지 않는다.
- 상태 선택지는 페이지의 현재 데이터 소스 스키마에서 읽는다. 여러 상태 속성이 있으면 사용자가 속성을 선택하며, 상태 속성이 없을 때만 이름이 `Status`·`상태`·`진행 상태`인 Select 속성을 지원한다.
- 한 번 조회한 카드의 상태 옵션은 앱 실행 중 메모리에 보관한다. 다시 열면 이전 목록을 즉시 표시하고 뒤에서 매번 재조회하며, 첫 조회에만 로딩 표시를 사용한다. 재조회 실패 시 이전 옵션과 오류 안내를 유지한다.
- 상태 옵션 캐시는 카드 패널을 닫아도 유지하되, 연결 토큰·뷰 변경 및 연결 해제 시 비운다. 현재 목록에서 빠진 카드의 캐시도 정리한다. 저장에 성공한 현재 선택값은 캐시에 즉시 반영하며 오래된 조회가 이를 덮지 못하게 한다. 실제 쓰기의 최신 속성·선택지 재검증은 유지한다.
- 상태 배지·선택지의 배경·글자·점은 Notion의 색상 토큰을 따른다. 2026-11-17 실제 Notion 밝은 테마의 CSS 색상을 기준으로 하며, 색상 누락·알 수 없는 토큰은 중립 회색으로 표시한다. 현재 앱은 밝은 테마만 제공한다.
- 상태 변경 직전에 속성·선택지 ID를 재검증하고 한 속성만 PATCH한다. 쓰기 권한 부족·삭제된 선택지·네트워크 실패를 한국어로 안내한다.
- 저장 성공 전에는 기존 상태를 유지한다. 저장 성공 뒤 뷰 재조회에 실패하면 성공한 변경은 유지하고 재조회 실패를 별도로 표시한다. 통신 중 결과가 불명확하면 새로고침으로 확인하도록 안내한다.
- 상태 변경·새로고침·연결 변경은 네이티브에서 직렬화하여 오래된 조회가 변경 결과를 덮지 않게 한다. 뷰 쿼리 생성·삭제는 조회용 임시 결과의 수명 관리에만 사용한다.
- 토큰은 OS 자격증명 저장소에 저장하고, 저장소 사용 실패 시 평문 파일로 대체하지 않는다.
- UI에는 토큰 존재 여부만 반환한다. 저장 완료 후 입력값을 비운다.
- 앱 설정과 카드 캐시는 로컬 데이터 파일로 보관하며 토큰은 포함하지 않는다.
- 인증·권한 오류와 빈 결과를 구분한다. 실패를 빈 카드 목록으로 바꾸지 않는다.
- 원본 열기는 조회한 카드의 식별자를 기준으로 처리한다.

## 후속 범위

| 항목 | 확장 시점에 결정할 내용 |
| --- | --- |
| Paca | 서버 주소·인증·저장된 필터 조회 계약. 현재 `http://localhost:3090` 로컬 서비스 확인 |
| 다중 모니터 | 모니터 선택·경계 이동·해상도 및 DPI 변경 정책 |
| 추가 카드 쓰기 | 본문·날짜·담당자 등 상태 이외 속성의 편집 필요성 |
| 캐릭터 리소스 | 자체 스프라이트와 애니메이션 교체 방식 |
| 고급 표현 | Live2D 또는 3D 렌더러·모델 리소스 선택과 전력 측정 |
| 배포 | 서명·공증·설치 파일·자동 업데이트 |

Paca의 쿼리 의미가 확인되기 전에는 공통 필터 언어를 만들지 않는다. Notion의 `viewId`와 Paca의 저장된 검색 식별자는 각 Provider가 해석한다.

## 수용 기준

| ID | 확인할 동작 | 검증 방식 |
| --- | --- | --- |
| AC01 | 주 모니터 작업 영역 밖으로 캐릭터·패널이 나가지 않음 | 좌표 로직 테스트 + OS 수동 확인 |
| AC02 | 카드 탐색·설정·드래그 중 자율 이동 정지 | 상태 로직 테스트 + 수동 확인 |
| AC03 | 빈 영역 클릭이 아래 앱에 전달됨 | macOS·Windows 수동 확인 |
| AC04 | 저장된 뷰의 필터·정렬과 카드 결과가 일치 | 실제 Notion 뷰와 비교 |
| AC05 | 권한·네트워크 오류 후 기존 카드와 실패 상태 유지 | 오류 경로 테스트 + 연결 중단 확인 |
| AC06 | 토큰이 설정 파일·카드 캐시·로그에 남지 않음 | 저장 코드 검토 + 실제 저장 파일 확인 |
| AC07 | 브라우저 미리보기에서 실제 토큰 연결 불가 | 브라우저 확인 |
| AC08 | 두 OS에서 프런트엔드·Rust 코드 빌드 가능 | CI 매트릭스 |
| AC09 | 대기·열람·숨김 상태에서 연속 애니메이션 루프가 없고 걷기·캐릭터 애니메이션은 최대 30 FPS로 제한 | 예약 작업·상태 전환 테스트 |
| AC10 | WebGL 경로를 식별할 수 있으며 초기화 실패·컨텍스트 손실 시 정적인 SVG 표시 | 브라우저 확인 + 렌더러 수명 주기 테스트 |
| AC11 | 상태 버튼에서 실제 스키마 선택지로 변경하고 원본 페이지는 열리지 않음 | API 모의 서버 + UI 확인 |
| AC12 | 잘못된 카드·속성·선택지는 쓰기 거부하며 다른 속성은 변경하지 않음 | API 요청 본문·명령 경계 테스트 |
| AC13 | 저장 중 중복 쓰기 방지, 실패 시 기존 상태 유지, 성공 후 저장된 뷰 재조회 | 비동기 UI·직렬화 테스트 |

CPU·GPU·전력은 동일 기기에서 대기, 이동, 카드 열람, 숨김 상태를 각각 측정한다. 절감률은 이전 구현과 같은 조건의 측정 결과가 있을 때만 기록한다.

완료 체크는 실제 검증 결과를 기준으로 기록한다. 초기 확인 목록:

- [ ] macOS 네이티브 이동·클릭 통과·포커스 전환
- [ ] Windows 네이티브 이동·클릭 통과·포커스 전환
- [ ] 실제 Notion 계정의 뷰 결과·정렬 비교
- [ ] 잠자기 복귀·오프라인 복귀·해상도 변경
