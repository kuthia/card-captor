# Codex 읽기 전용 관측

## 목적과 지원 범위

Codex 앱의 Mini와 유사한 피드 생성·상태 알림·사운드 반응을 Card Captor에서 제공한다. Codex 내부 모듈 교체가 아니라 외부 관측자이며, 비공개 데스크톱 IPC에 의존하는 비공식 구현이다. 공식 App Server로 별도 세션을 실행하지 않는다.

2026-11-18 설치된 macOS Codex 앱 `26.1111.21308`의 stream version 13을 기준으로 확인했다. Unix 소켓을 사용하는 macOS·Linux에서 실행되며 실제 연결 검증은 macOS에서 수행했다. Windows named pipe와 원격·클라우드 작업은 후속 범위다. 버전 불일치는 명시적인 연결 오류로 처리한다.

## 동작과 경계

| 항목 | 동작 |
| --- | --- |
| 소켓 | `CODEX_HOME/ipc/ipc.sock`, `~/.codex/ipc/ipc.sock`, UID별 임시 경로 순으로 탐색. 소켓·부모 디렉터리의 UID, 부모 쓰기 권한, 연결 peer UID 확인 |
| 초기 발견 | 최근 14일 세션 파일의 **이름·수정 시각만** 확인해 최대 32개 UUID 후보 선정. 파일 내용을 읽거나 세션을 resume하지 않음 |
| 작업 구독 | 소유자 조회에 응답한 앱 클라이언트의 작업과 이후 선택 이벤트를 따라 최대 12개 관측 |
| 상태 | 작업 중·확인 필요·완료·실패·중단·대기. idle만으로 완료를 추정하지 않음 |
| 최신 턴 | legacy 배열 순서 또는 canonical history의 최신 페이지 경계·entry 순서를 사용. 과거 페이지만 로드된 상태는 현재 완료의 근거로 쓰지 않음 |
| 말풍선 | 제목 1줄·최신 assistant 진행 내용 1줄. 작업 중·입력 대기 동안 실시간 갱신. 완료·실패·중단은 6.5초 후 숨김. 최초 과거 완료는 표시하지 않음 |
| 알림 | 관측 이후 확인 요청·완료·실패 전이에서 활동 추가, 선택한 OS 알림·사운드 표시. 말풍선은 OS 알림 설정과 독립 |
| 중복 | 대화·턴·상태·요청 식별자로 억제. 최초·재연결·revision 복구 snapshot은 알림 없음 |
| 연결 해제 | 마지막 상태에 오래된 데이터 표시. 1~30초 재연결 대기. 관측 해제 시 구독 해제 후 대기 |
| 열기 | 팝업 피드의 작업·최근 활동 항목 전체를 클릭하거나 Enter/Space로 실행하면 관측된 UUID의 `codex://threads/{id}` 열기. 현재 작업에서 빠져도 최근 활동에 있으면 허용 |

전송 허용 메시지는 초기 등록(`initialize`), 소유자 조회(`thread-owner-discovery`), 관측 구독/해제(`thread-stream-following-changed`), 다른 클라이언트 요청을 처리하지 않겠다는 discovery 응답뿐이다. 작업 시작·수정·중단·steer·승인·설정 변경 메시지를 생성하는 경로는 없다. 구독 자체는 Codex의 follower 등록 상태를 바꾸지만 업무 내용은 변경하지 않는다.

## 데이터·알림

- IPC 프레임과 대화당 보관 상태는 각각 8 MiB 이하. add/replace/remove patch만 허용하고 copy 증폭을 차단한다. 작업 12개·활동 40개·중복 키 512개를 메모리에 한정한다.
- raw 대화는 patch 병합에 필요한 메모리에만 유지한다. UI에는 제목 90자와 마지막 assistant 응답 160자까지 투영하고, OS 알림에는 상태와 제목만 전달한다. 전체 대화나 도구 인자를 파일·진단 출력에 기록하지 않는다.
- 관측·알림·사운드는 기본 켜짐이며 앱 데이터 폴더의 `codex.json`에 독립 저장한다. 임시 파일을 쓴 뒤 교체하고 실패 시 기존 설정을 유지한다. 읽기 실패·손상 시 관측을 끄고 오류를 표시한다.
- 사운드는 직접 합성한 `src-tauri/assets/codex-chime.wav`이며 macOS `afplay`, Linux `paplay`를 고정 인자로 호출한다. 2초 이내 연속 소리를 제한한다. Linux는 해당 재생기 설치가 필요하다.
- OS 알림 표시 여부는 운영체제 권한·집중 모드에 따르며, API 호출 성공만으로 배너 노출을 보장하지 않는다.
- 브라우저 시나리오는 명시적인 합성 데이터이며 실제 IPC·OS 알림·사운드를 사용하지 않는다. 측정 모드에서는 설정 접근·observer 시작·외부 앱 열기·알림을 차단한다.

## 검증

2026-11-18 macOS arm64에서 다음을 확인했다.

- production observer를 실행하는 `codex-observe-probe`로 실제 앱의 로컬 작업 4개를 수신했다. 턴·상태·응답 요약이 있었고 최초 관측 알림은 없었다. 진단에는 작업 제목·본문·UUID를 출력하지 않았다.
- duplex 가짜 IPC 서버와 실제 session 함수를 연결해 등록→소유자 발견→구독→snapshot→완료 patch→알림 생성→구독 해제를 검증했다. Codex 업무를 변경하는 메시지는 보내지 않았다.
- revision 누락과 재기준화, 최초·재접속 완료 중복 억제, 새 턴 완료, 승인 요청 식별, canonical 순서, 단편 프레임·초과 크기, unsafe socket, 설정 재실행·저장 실패·측정 격리를 자동 검증했다.
- 브라우저에서 합성 확인 요청·완료 피드, 관측 해제 후 이벤트 억제, 390×844 레이아웃을 확인했다.
- 실제 데스크톱 위젯에서 작업 4개·완료 상태를 확인했고, 알림 테스트에서 번들 음원 파일 생성과 재생 명령 호출에 오류가 없었다.

### Mini 표시 보완

- 프런트엔드 50개·네이티브 43개 테스트로 같은 상태의 진행 내용 갱신, 최초 완료 숨김, 완료 표시 만료, 입력 대기 유지, 연결 끊김·관측 해제, 다른 작업으로 복귀, 최근 활동 URI 허용 범위를 검증했다.
- 브라우저에서 제목·내용 각각 한 줄의 말풍선과 진행 내용 변경, 팝업 피드 항목의 전체 클릭 영역을 확인했다.
- 실제 데스크톱 피드의 항목을 눌러 Codex 앱 창이 해당 대화 제목으로 전환되는 것을 확인했다.

실제 Codex 업무를 시험용으로 시작하거나 승인하지 않았다. 실제 OS 배너 노출, Linux 실행, Windows named pipe는 이 결과로 검증되지 않는다.

관련 공개 구현은 [codex-token-overlay의 IPC 모니터](https://github.com/soleillevant0125/codex-token-overlay/blob/f35ef46298225fa69c1775701d95db30cb74eaf8/macos/Sources/CodexTokenCore/CodexIPCMonitor.swift)다. 등록·선택 관측 방식의 참고 자료이며 해당 프로젝트 코드를 복사하지 않았다.
