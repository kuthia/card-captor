# 캐릭터 리소스와 애니메이션 사양

캡터는 코드에 포함된 SVG 몸통을 PixiJS 텍스처로 변환하고 눈·그림자·안테나를 합성한다. 웰루니는 캐릭터보드에서 파생한 로컬 투명 PNG를 사용하고, Centaur는 번들 Rive 샘플을 사용한다. 캐릭터 선택 패널에서 세 캐릭터를 미리 보고 변경한다. 외부 스프라이트·atlas·사용자 모델 로더는 아직 없다. 이 사양의 Pixi 좌표·레이어 항목은 캡터에 적용한다.

리소스·좌표·애니메이션 설정은 TypeScript 상수와 렌더링 코드에 고정되어 있다. 이 설정을 외부 JSON으로 읽거나 사용자 이미지를 불러오는 경로는 없다.

선택값은 `AppConfig.characterId`의 `robot`·`welluni` 중 하나다. 데스크톱에서는 `set_character` 명령이 토큰이나 Notion 연결을 조회·수정하지 않고 선택값만 원자적으로 저장한다. 저장 실패 시 메모리의 선택도 바꾸지 않는다. 이전 설정에 선택값이 없으면 `robot`을 사용한다. 브라우저에서는 `card-captor.character` 로컬 저장소 키를 사용하며, 읽기 실패·알 수 없는 값은 `robot`으로 복구한다. Notion 연결 해제는 캐릭터 선택을 유지한다.

## 크기와 좌표

좌표 단위는 CSS 픽셀이며 원점은 캐릭터 왼쪽 위다. SVG `viewBox`와 Pixi 논리 좌표는 모두 `0 0 168 160`을 사용한다.

| 항목 | 현재 값 |
| --- | --- |
| 캐릭터 표시·캔버스 크기 | 168 × 160 |
| 클릭·드래그 및 이동 경계 계산 영역 | 168 × 180. 캐릭터 아래 캡션 포함 |
| 캡터 SVG 텍스처·캔버스 배율 | `devicePixelRatio`를 1 이상 2 이하로 제한. 웰루니 PNG는 원본 해상도로 로드 |
| 캔버스 최대 backing 크기 | 336 × 320 픽셀 |
| 몸통 컨테이너 기준점 | pivot·기본 position 모두 `(75, 140)` |
| 눈 도형 | `(58, 54, 7, 11)`, `(83, 54, 7, 11)`, 모서리 반지름 3.5 |
| 눈 컨테이너 기준점 | `(74, 60)` |
| 그림자 | 중심 `(77, 146)`, 반지름 `(43, 6)`, 불투명도 0.12 |
| 열람 표시용 안테나 | 중심 `(75, 17)`, 반지름 3.7, 색 `#AECBAD` |
| 카드 개수 배지 | 중심 `(140, 58)`, 반지름 12 |

배율은 렌더러를 생성할 때 결정한다. 실행 중 DPR 변경에 맞춘 텍스처·캔버스 재생성은 구현되어 있지 않다. 크기를 바꿀 때는 `CHARACTER_SIZE`뿐 아니라 `art.ts`의 SVG 크기·viewBox, `Robot.tsx`의 SVG와 배지 좌표, Pixi 도형·기준점, `App.tsx`의 `PET`, CSS 크기도 함께 변경해야 한다.

## 레이어와 표시

WebGL의 그리기 순서는 그림자 → 몸통 텍스처 → 눈 → 열람 표시용 안테나다. 몸통·눈·안테나는 하나의 `figure` 컨테이너로 변환하고, 그림자는 고정한다. 몸통 텍스처에는 다리·팔·들고 있는 카드가 함께 포함되어 있어 각 부위를 독립적으로 움직이지 않는다.

웰루니는 같은 캔버스 안에 PNG의 종횡비를 유지해 맞춘다. 로봇용 눈과 안테나는 숨긴다. 보행·드래그는 전체 몸체의 회전·상하 이동으로 표현하며, 대기 중에는 눈깜빡임 예약도 하지 않는다. 캐릭터보드의 다른 표정·방향별 포즈 전환은 아직 제공하지 않는다.

카드 개수는 WebGL 바깥의 SVG 레이어로 표시한다. 0개이면 숨기고, 1–99개는 숫자, 100개 이상은 `99+`를 표시한다. 개수 변경은 캐릭터 텍스처 재생성과 무관하다. 이미지 안에 숫자나 연결 상태 문구를 넣지 않는다.

캔버스와 개수 배지는 포인터 입력을 받지 않는다. `App.tsx`의 바깥 버튼이 클릭·드래그·포커스를 처리하고, 화면상 위치는 버튼의 CSS `translate3d`로 반영한다. 렌더러는 화면 이동 좌표를 소유하지 않는다.

## 상태와 애니메이션

행동 우선순위는 `dragging` → `browsing` → `suspended` → `walk` 또는 `idle`이다. 카드·설정·캐릭터 선택 패널을 열면 `browsing`, 산책 중지·숨김·동작 줄이기 조건에서는 `suspended`로 판단한다. 포인터를 캐릭터 위에 두면 자율 이동을 멈추고 `idle`이 된다. [상태 결정 코드](../src/motion.ts)

| 상태 | WebGL 표현 | 지속 갱신 |
| --- | --- | --- |
| `idle` | 기본 자세와 눈깜빡임 | 눈깜빡임 시작·종료 시에만 그림 |
| `walk` | 몸통 좌우 회전과 상하 움직임 | 최대 30FPS 목표 |
| `dragging` | 회전 −0.12rad, 기본 높이보다 5px 위 | 자세 변경 시 그림. 위치는 포인터 입력으로 이동 |
| `browsing` | 기본 자세, 초록색 안테나 표시 | 상태 변경 시에만 그림 |
| `suspended` | 기본 정지 자세 | 상태 변경 시에만 그림 |

| 설정 | 값과 의미 |
| --- | --- |
| `CHARACTER_FPS` | 30. 실제 표시 FPS 측정값이 아닌 상한 목표 |
| `CHARACTER_FRAME_MS` | `ceil(1000 / 30)` = 34ms |
| 보행 위상 | `elapsedMs / 580 × 2π`. 580ms 주기 |
| 보행 회전 | `sin(phase) × 0.018rad` |
| 보행 높이 | 기본 y=140에서 `−abs(sin(phase)) × 3px` |
| `IDLE_BLINK_AFTER_MS` | 기본 자세를 그린 뒤 눈감기까지 6000ms |
| `BLINK_DURATION_MS` | 눈감기 110ms. 다시 뜬 뒤 다음 눈감기까지 6000ms |
| 눈감기 표현 | 눈의 세로 배율 0.12 |
| `paused` | 첫 정지 프레임만 그리고 추가 예약을 중지. 경과시간은 0 |

애니메이션 시계는 `performance.now()`와 `setTimeout`을 사용한다. 상태·일시 정지·복구가 바뀌면 경과시간을 다시 시작한다. 이동 예약과 렌더링 예약은 각각 34ms 간격이며 화면 주사율에 동기화된 하나의 루프는 아니다. CSS에 남아 있는 `breathe`·`step` 키프레임은 현재 렌더러의 애니메이션 설정으로 사용하지 않는다.

화면 이동은 별도 정책이다. 속도는 35 CSS px/s, 한 번의 경과시간은 최대 100ms로 제한한다. 일반 모드는 최초 3500ms 후 이동을 시작하고, 목적지에 도착하면 2500–7000ms 대기한다. 목적지는 작업 영역에서 캐릭터 영역과 18px 여백을 고려해 제한한다. 이동 방향별 프레임·좌우 반전·시선 방향은 현재 계약에 없다. [이동 정책](../src/activity-policy.ts), [좌표 갱신](../src/motion.ts)

## 렌더러 계약과 리소스 수명

`CharacterFrame`은 `state`, `elapsedMs`, `blink`를 전달한다. `CharacterRenderer`는 현재 `kind: 'webgl'`, `render(frame): boolean`, `destroy(): void`를 제공한다. `render`가 `false`를 반환하면 연속 예약을 중지한다. 이 인터페이스는 JS 캔버스 렌더러 경계이며 네이티브 오버레이와 직접 호환되는 계약은 아니다. [계약](../src/renderer/contract.ts)

- PixiJS는 지연 로드하며 WebGL2 투명 캔버스를 생성한다. `antialias: false`, `backgroundAlpha: 0`, `preserveDrawingBuffer: false`를 사용한다.
- `powerPreference: 'low-power'`는 선택 힌트다. 실제 GPU 선택이나 전력 절감을 보장하지 않는다.
- 자동 Ticker·주기적 GPU GC·Pixi 포인터 이벤트를 사용하지 않고, 소유자가 직접 그리기와 해제를 수행한다.
- 언마운트 시 이미지 로딩을 취소하고 예약·이벤트·텍스처·컨테이너·렌더러를 해제한다. 늦게 완료된 초기화도 `RendererLifetime`에서 해제한다.
- SVG 원본은 신뢰된 코드 상수만 사용하고 PNG는 로컬 번들만 로드한다. 정적 대체 SVG에도 같은 원본을 사용한다. 외부 SVG·HTML 문자열을 그대로 삽입하는 경로로 확장하지 않는다.
- 캐릭터 변경 시 이전 캔버스·렌더러를 해제한다. 캡터·웰루니 미리보기는 정적 이미지, Rive 미리보기는 정지한 로컬 WebGL 모델을 사용한다.
- CSP는 로컬 script와 Rive WASM 실행에 필요한 `wasm-unsafe-eval`을 허용한다. `pixi.js/unsafe-eval` import는 동적 코드 생성을 대체하는 구현이며 일반 JavaScript `unsafe-eval`은 허용하지 않는다. [CSP 설정](../src-tauri/tauri.conf.json)

## 정적 대체와 복구

| `data-renderer` | 표시와 동작 |
| --- | --- |
| `initializing` | 준비 중 정적 SVG 표시 |
| `webgl` | WebGL 캔버스와 별도 개수 배지 표시 |
| `svg-fallback` | 초기화·그리기 실패 후 정적 SVG 표시 |
| `context-lost` | 정적 SVG로 표시하며 WebGL 컨텍스트 복구 대기 |

정적 SVG는 몸통·눈·그림자를 표시하고 연속 애니메이션을 하지 않는다. 드래그 중이고 `paused`가 아니면 −7° 회전과 −5px 이동 자세를 적용한다. WebGL의 열람 안테나 강조는 정적 대체에 포함되지 않는다. 개수 배지와 바깥 버튼의 화면 이동은 계속 사용할 수 있다.

웰루니의 정적 SVG는 내부 `<image>`로 같은 로컬 PNG를 표시한다. 초기화 실패·컨텍스트 손실 시에도 선택한 캐릭터를 유지한다.

컨텍스트가 복구되면 현재 상태의 첫 프레임을 그린 뒤 애니메이션 예약을 다시 시작한다. 복구 중 그리기가 실패하면 렌더러를 해제하고 정적 SVG로 전환한다. [연결·복구 코드](../src/Robot.tsx), [소유권 처리](../src/renderer/lifetime.ts)

## 캐릭터 교체 기준

현재 그림을 바꿀 때는 `art.ts`의 몸통·정적 눈·그림자와 `pixi.ts`의 눈·그림자·안테나 좌표를 함께 맞춘다. 몸통의 회전·이동 기준점을 `(75, 140)`에 맞추고, 개수 배지와 상하 움직임이 잘리지 않도록 168 × 160 영역 안에 여백을 둔다. WebGL과 정적 대체의 자세·색·기준점을 각각 확인한다.

새 렌더러를 도입해도 카드 Provider·카드 목록·화면 이동을 렌더러 안으로 옮기지 않는다. 상태 입력, 수동 그리기, 해제, 컨텍스트 실패 처리의 책임을 유지한다. [전체 구조](architecture.md)

외부 스프라이트 시트를 도입하는 시점에는 아래 항목을 추가로 확정해야 한다. 현재 이를 읽는 atlas 로더나 파일 형식은 구현되어 있지 않다.

- 이미지 형식·경로·배율과 프레임 크기·간격·패딩
- 공통 기준점·접지점·클릭 영역 및 그림자 포함 여부
- 현재 다섯 상태의 프레임 매핑·재생률·반복 정책
- 방향 전환·눈깜빡임·개수 배지를 분리할지 여부
- 누락된 상태·로딩 실패·동작 줄이기의 정지 프레임

교체 후에는 유휴·열람·중지 상태의 연속 예약 여부, 상태 변경 시 이전 예약 취소, 늦은 초기화 해제, WebGL 실패·복구를 확인한다. 기존 [애니메이션 테스트](../src/renderer/animation.test.ts)와 [수명 주기 테스트](../src/renderer/lifetime.test.ts)는 이 계약을 검증한다.

## Rive 선택과 별도 검증 모드

일반 모드의 카드 패널에서 **캐릭터**를 선택하면 `AppConfig.characterBackend`에 `robot` 또는 `rive`를 저장한다. 필드가 없는 기존 설정은 `robot`으로 읽는다. 선택 저장은 전용 네이티브 명령으로 처리해 토큰을 읽거나 카드 목록을 다시 만들지 않는다. 검증 모드와 브라우저 미리보기에서는 선택을 메모리에만 둔다.

Rive는 공식 `Centaur` 모델을 사용하며 대기·카드 열람 중에도 모델 애니메이션을 갱신한다. 크기·카드 배지·이동·드래그 입력은 기존 앱이 유지한다. 모델의 출처는 [Rive 자산 문서](rive-assets.md), 행동 매핑·시계·모드별 실행 방법은 [Rive 동작 검증](rive-validation.md)을 따른다.
